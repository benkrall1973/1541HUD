# 1541HUD V0.0.32-RC1 Hardware Test Plan

## Purpose

V0.0.32-RC1 is the first integrated release candidate that combines the selected hardware-tested T0.x features into one deliberately versioned firmware/GUI pair.

RC1 is not V0.0.32 yet. Promotion happens only after this exact integrated build is reproduced, hashed, and verified on real Commodore 1541 hardware.

## Build

From the project root in PowerShell:

```powershell
.\1541hud\Build-1541HUD-Current.ps1
```

Expected RC outputs are created under:

```text
OneROM\build-1541hud\
```

including:

```text
1541HUD_OneROM_V0.0.32_RC1.bin
1541HUD_OneROM_V0.0.32_RC1.uf2
1541hud_probe_v0032_rc1_SOURCE.c
usb_main_v0032_rc1_SOURCE.c
```

Record the SHA256 values printed by the builder.

## GUI

Run:

```text
1541hud/gui/1541HUD_V0.0.32_RC1.py
```

The window title and visible firmware identity should both identify `V0.0.32-RC1`.

Before HOME has been observed, the GUI should clearly state that the absolute track reference is not confirmed and should advise homing after a ROM change/reset. After a real Track-1 HOME event it should show:

```text
HOME: anchored at Track 1.0
```

## Minimum hardware validation

1. Confirm drive boots normally and can read a directory with 1541HUD installed.
2. Confirm GUI connects when started before the drive and after the drive.
3. Confirm reconnect/state resend behavior.
4. Confirm motor ON/OFF.
5. Confirm head IN / OUT / STALL / PARK.
6. Confirm HOME anchor resets the display to Track 1.0.
7. Confirm half-track movement, including diagnostic-cartridge manual half-steps if available.
8. Confirm write-protect state.
9. Confirm density D0-D3 behavior.
10. Confirm RPM near the known physical value during normal reads.
11. Confirm last-decoded sector updates.
12. Confirm the 10-entry recent-sector FIFO updates and clears on seek/motor off as designed.
13. Confirm raw PB7/SYNC activity is 0 with motor off and approximately zone-correct when reading a normal formatted disk.
14. Confirm SYNC/rev estimates settle near 42/38/36/34 in D3/D2/D1/D0 respectively.
15. Confirm last-good RPM is held during seeks rather than showing the previously observed ~283 RPM reacquisition artifact.
16. Confirm the first mixed post-seek SYNC report is hidden and the next clean report appears normally.
17. Load a real game with the original Commodore ROM.
18. Change to JiffyDOS, HOME the drive, and load the same game again; confirm absolute track display is sane after HOME and monitoring remains passive.

## Wiring reminder

Current passive monitor taps:

```text
UC4 pin 34  R/W       -> OneROM GPIO9
UC4 pin 39  PHI2      -> OneROM GPIO8
UC2 pin 23  /CS2      -> OneROM GPIO25
UC2 pin 17  PB7/SYNC  -> OneROM GPIO24

UB4 pin 20            -> UB3 X1
```

See `docs/HARDWARE-WIRING.md` for the complete two-OneROM installation description.

## Promotion criteria

Do not tag or publish V0.0.32 until:

- the exact RC1 firmware build succeeds from the committed builder;
- BIN/UF2/source hashes are recorded;
- the exact RC1 UF2 is hardware-tested;
- the matching RC1 GUI is hardware-tested;
- no regression is found in the V0.0.30/V0.0.31 baseline functions;
- the final GUI screenshot is captured for the README;
- documentation and changelog match the tested image;
- the exact tested commit is identified.

If RC1 needs any runtime change, create RC2 rather than silently changing the tested RC1 identity.
