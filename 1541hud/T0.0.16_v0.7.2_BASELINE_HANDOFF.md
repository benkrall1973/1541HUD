# 1541HUD T0.0.16 — OneROM v0.7.2 Baseline Port

## Purpose

Port the hardware-proven 1541HUD V0.0.32 UB4 passive monitor onto a clean upstream OneROM v0.7.2 source base without intentionally changing the underlying monitor algorithms or UB4 wiring.

T0.0.16 is a temporary development baseline, not a public release.

## Hardware status

T0.0.16 has been tested successfully on the UB4 passive-monitor OneROM in a Commodore 1541.

The tested UB4 monitor behavior includes:

- normal drive boot and directory access
- USB CDC communication
- authoritative STATE telemetry
- physical SYNC telemetry
- track and half-track tracking
- HOME re-anchor at Track 1.0
- motor ON/OFF
- head movement / STALL / PARK
- write-protect status
- density D0-D3
- physical sector/header decoding
- RPM measurement
- SYNC/sec and SYNC/revolution estimation
- recent-sector FIFO display
- correct motor-off cleanup in the T0.0.16 GUI

Observed running RPM values were approximately 300 RPM and the GUI reached `RPM STATE: FRESH`.

This hardware proof applies to the UB4 passive 1541HUD monitor only. It does not validate future UB3 active-control functions such as address switching, RAM-slot control, host reset control, or other active bus operations.

## OneROM v0.7.2 port

The embedded OneROM source base was replaced with upstream OneROM v0.7.2.

The following 1541HUD-specific behavior was reapplied:

- UB4 passive-safety hook in `OneROM/firmware/src/piodma/pio.c`
- dedicated 1541HUD PIO/DMA capture
- `/CS2`-only UC2 qualification
- GPIO24 physical SYNC input
- T0.0.16 user plugin
- existing 1541HUD mailbox / CDC telemetry bridge on the native v0.7.2 USB plugin

The passive safety hook prevents normal ROM-serving PIO from starting when `HUD1541_PASSIVE_UB4` is defined, preserving the requirement that the UB4 monitor must not drive the 1541 bus.

## OneROM v0.7.2 capabilities retained

The v0.7.2 USB plugin infrastructure is retained, including `usb_log.c` and the plugin uptime/logging APIs.

T0.0.16 does not yet migrate 1541HUD telemetry to the OneROM logging API. The existing authoritative mailbox / CDC path remains in use for this baseline.

OneROM v0.7.2 log output was observed interleaved correctly on the CDC connection during testing.

## GUI

Stable historical GUI source remains untouched.

T0.0.16 uses:

`1541hud/gui/1541HUD_T0.0.16.py`

The temporary GUI wrapper accepts the T0.0.16 telemetry identity while preserving the previously proven RPM, sector, SYNC, HOME and display behavior.

Required T0.0.16 compatibility fixes included:

- accepting `T0.0.16` in STATE / STATUS parsing
- accepting `T0.0.16` in RPM / HDRPHY / SYNC parsing
- preserving `MOTOR OFF` state after a final phase event
- preventing post-motor-off phase handling from incorrectly returning RPM state to `ACQUIRING (SEEK)`

Historical `1541HUD_T0.0.18_RPM_Hold_Qualification_Test.py` was restored unchanged after the T0.0.16-specific fix was moved into the T0.0.16 wrapper.

## Toolchain

OneROM v0.7.2 requires the Arm GNU 15.3.rel1 toolchain used by its upstream source.

Installed toolchain:

```text
/opt/arm-gnu-toolchain-15.3.rel1/bin
arm-none-eabi-gcc 15.3.1
```

The older WSL `arm-none-eabi-gcc` 10.3.1 toolchain failed the v0.7.2 linker constraints.

The T0.0.16 builder now defaults to:

```text
/opt/arm-gnu-toolchain-15.3.rel1/bin
```

From Git Bash, use `MSYS_NO_PATHCONV=1` when invoking PowerShell so `/opt/...` is not rewritten into a Windows path.

Example:

```bash
MSYS_NO_PATHCONV=1 powershell.exe -ExecutionPolicy Bypass \
  -File "$(cygpath -w "$PWD/1541hud/Build-1541HUD-T016-v072-Baseline.ps1")" \
  -OneRomCli "C:\Users\Admin\Desktop\onerom-cli-win-0.3.0-x86_64\onerom.exe"
```

## Stable baseline preservation

The hardware-proven V0.0.32 source, GUI and builder remain preserved and are not modified by T0.0.16 development.

T0.0.16 exists to establish a clean, reproducible OneROM v0.7.2 development baseline before any future control-plane simplification or UB3 active-control work.
