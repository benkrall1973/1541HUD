# T0.0.21 — UB3 C64 temporary IEC-address proof

## Purpose

This is the smallest practical proof that a C64 can change the attached 1541's **live** IEC address without a Nano IEC controller, additional wiring, a OneROM ROM patch, or any modification of the UB3 JiffyDOS image.

It uses the same standard DOS mechanism already used by the OneROM selector: the C64 writes a nine-byte routine into the idle drive's RAM with `M-W`, then executes it with `M-E`.

The temporary 1541 routine is:

```asm
LDA #new_address
STA $0077
STA $0078
RTS
```

This changes only volatile 1541 RAM. A drive reset or power cycle restores its normal configured address.

## Scope and guardrails

- Targets a drive that is currently at **device 8** only.
- The generated default target is **device 10**.
- Do not run it unless device 10 is free. The Ultimate-II+ normally occupies device 9, which is why this proof defaults to 10.
- Ensure the drive is idle and only one physical 1541 is powered during the first test.
- This is temporary: it does not touch UB3 flash slots, JiffyDOS, the bootloader, write-protect hardware, or 1541HUD UB4 firmware.
- It does not yet provide a GUI, an idle interlock, collision scan, persistent address, or automatic rollback.
- Recovery is simple: power-cycle the 1541.

## Build

From Git Bash:

```bash
cd /c/1541HUD_LOCAL
git fetch origin
git switch --track origin/t0.0.21-ub3-c64-address-proof

MSYS_NO_PATHCONV=1 powershell.exe -NoProfile -ExecutionPolicy Bypass \
  -File "$(cygpath -w 1541hud/Build-1541HUD-T021-UB3-C64-AddressProof.ps1)" \
  -NewAddress 10
```

The PRG is created in:

```
1541hud/build-address-test/1541HUD_UB3_T0.0.21_Set_Address_8_to_10.prg
```

## Test

1. Start with the 1541 at device 8 and idle.
2. Confirm device 10 is unused.
3. Load the generated PRG from the Ultimate-II+ or other C64 media and run it.
4. It returns to BASIC after sending the request.
5. On the C64, verify the new address with:

   ```basic
   LOAD"$",10
   LIST
   ```

6. Power-cycle the 1541. It should return to address 8.
7. Verify recovery:

   ```basic
   LOAD"$",8
   LIST
   ```

A failure to verify at 10 is not a reason to probe repeatedly. Power-cycle the drive and return to 8 before reporting the result.

## Why this is the right first test

The result tells us whether ordinary C64 IEC control is sufficient for temporary address management on this specific JiffyDOS/UB3 setup. If it passes, the later GUI can call the same mechanism through a deliberately designed C64-side helper rather than requiring an external Arduino bus master.
